## 二、当前状态分析

### 2.1 现有逻辑现状

通过代码审查，确认以下现状：

**需求 1（裁员后掷骰子）**：当前逻辑实际上已经允许失业玩家掷骰子移动，`ratRaceRollDice` 没有检查 `isUnemployed`。问题在于 UI 上缺少失业状态的视觉提示，且 `unemploymentTurns` 递减逻辑已在 `moveToNextPlayer` 中正确实现。

**需求 2（市场风云多玩家）**：当前 `applyMarketEvent` 仅作用于当前玩家，`sellAssetToMarket` 也只操作当前玩家资产。其他玩家完全无法感知市场风云事件，也无法卖出。

**需求 3（慈善双骰）**：`doubleDiceNextTurn` 字段和核心逻辑已实现，但 UI 上无任何提示。

**需求 4（骰子动画）**：无动画，直接出结果。`rollDice` 函数直接返回随机数。

**需求 5（正方形棋盘）**：当前是流式网格布局（`grid-cols-3 sm:grid-cols-4 lg:grid-cols-6`），24 个格子按顺序排列，非环形赛道。

**需求 6（资产卖出）**：仅当前玩家在市场风云 pending 面板中可卖出，无数量选择，入口不明显。

## 三、详细实施方案

### 需求 1：裁员后可继续掷骰子

**What**：确认失业期间玩家可正常移动和触发格子事件（仅停发工资），并增强 UI 提示。

**Why**：Cashflow 规则中失业只是没有工资，玩家仍可继续游戏、投资、交易。

**How**：
1. 确认 `ratRaceRollDice` 中没有阻止失业玩家掷骰子的逻辑（已确认没有）
2. 在顶部玩家信息栏添加"失业中"徽章，显示剩余回合数
3. 失业期间经过 payday 格子时消息明确说明"失业中，仅扣除支出"
4. 2 回合后自动恢复工作的逻辑已存在，验证即可

**修改文件**：
- `src/views/RatRaceView.vue` — 顶部栏新增失业状态徽章
- `src/stores/game.ts` — 优化失业期间消息文案

**验证**：落到裁员格 → 仍可掷骰子 → 经过发工资格只扣支出 → 2 回合后恢复

### 需求 3：慈善双骰视觉反馈

**What**：为慈善后的双骰效果增加多层视觉提示。

**Why**：当前逻辑已实现但 UI 完全不可见，玩家不知道自己有双骰 buff。

**How**：
1. **顶栏徽章**：当前玩家信息旁显示"双骰"图标徽章（Dices 图标），带轻微呼吸动画
2. **按钮状态**：`doubleDiceNextTurn` 为 true 时，掷骰子按钮文字改为"掷双骰"，显示两个骰子图标
3. **消息提示**：掷出双骰时，消息中明确显示两个骰子点数及总和
4. **捐赠成功动效**：接受慈善后，双骰图标从按钮处弹起（简单的 CSS 过渡）

**修改文件**：
- `src/views/RatRaceView.vue` — 顶栏徽章、按钮状态、消息样式
- `src/stores/game.ts` — 返回双骰各自点数（拆分为 dice1 + dice2）

**验证**：捐赠 → 顶栏出现双骰徽章 → 按钮显示"掷双骰" → 掷出后显示两个点数 → 使用后徽章消失

### 需求 4：掷骰子动画效果

**What**：新增骰子滚动动画组件，点击后骰子翻滚 0.8-1.2 秒再出结果。

**Why**：当前直接出结果，缺乏游戏感和仪式感。

**How**：
1. 创建 `DiceRoller.vue` 组件
   - 骰子面用 CSS 绘制（1-6 点，经典骰子布局）
   - 翻滚效果：快速切换随机点数 + 旋转弹跳动画
   - 支持单骰/双骰模式
2. 集成交互流程：
   - 点击掷骰子 → 显示骰子动画叠加层 → 预计算随机数 → 动画播放 → 动画结束触发实际移动
   - 利用现有 `turnStatus: 'rolling'` 状态
3. 快车道页面同样集成（默认双骰）

**关键决策**：CSS + JS 驱动，不引入额外库。先算好结果再播动画（保证结果一致）。

**修改文件**：
- `src/components/DiceRoller.vue` — 新增组件
- `src/views/RatRaceView.vue` — 集成分量
- `src/views/FastTrackView.vue` — 集成分量
- `src/stores/game.ts` — 可选：拆分"预计算点数"与"执行移动"

**验证**：点击 → 动画播放 → 结果正确 → 不可重复点击 → 单/双骰都正常

### 需求 5：正方形大富翁式棋盘

**What**：将老鼠赛跑棋盘从流式网格改为正方形环形赛道（大富翁样式）。

**Why**：更符合经典桌游视觉，增强沉浸感，中间区域可利用。

**How**：
1. 创建 `RatRaceBoard.vue` 组件，抽取棋盘逻辑
2. **布局方案**：absolute 定位 + 位置计算函数
   - 24 格环绕四边：上 7 格（0-6）、右 5 格（7-11）、下 7 格（12-18）、左 5 格（19-23）
   - 棋盘容器 `aspect-square`，格子按百分比定位
   - 起点（索引 0）位于左下角，顺时针方向
3. **中间信息区**：
   - 当前玩家核心数据（现金、月现金流、资产数）
   - 当前骰子点数（掷骰后显示）
   - 回合数
4. **玩家棋子**：
   - 彩色圆点头像，当前玩家高亮
   - 移动时 CSS transition 平滑过渡
5. **响应式**：移动端格子尺寸缩小，中间信息简化

**修改文件**：
- `src/components/RatRaceBoard.vue` — 新增棋盘组件
- `src/views/RatRaceView.vue` — 替换原有网格为新组件
- `src/data/board.ts` — 可选：调整格子顺序以匹配环形布局

**验证**：24 格形成完整正方形 → 移动沿环进行 → 中间信息正确 → 各尺寸下保持正方形

### 需求 2：市场风云对所有玩家生效

**What**：抽到市场风云卡时，所有持有相关资产的玩家都可以选择卖出。

**Why**：市场是公共的，股价变动对所有持股玩家都有影响。

**How**：
1. **状态机设计**：新增 `marketEventState`
   ```ts
   interface MarketEventState {
     card: MarketEventCard
     currentResponderIndex: number  // 当前轮到回应的玩家
     respondedIds: Set<string>      // 已回应玩家
     phase: 'current_player' | 'other_players' | 'done'
   }
   ```
2. **交互流程**：
   - 当前玩家落到市场格 → 抽卡 → 显示事件 → 当前玩家操作
   - 当前玩家完成 → 轮询其他持有相关资产的玩家 → 依次切换操作
   - 每个玩家可选择卖出（可选择数量）或跳过
   - 全部操作完 → 市场事件结束 → 回到当前玩家回合
3. **Store 方法**：
   - `advanceMarketResponder()` — 推进到下一个回应玩家
   - `sellAssetForPlayer(playerId, assetId, qty)` — 指定玩家卖出
   - `dismissMarketForResponder()` — 当前玩家跳过
4. **UI**：市场面板顶部显示"玩家 X 操作中"，底部显示进度（3/5 玩家已操作）

**修改文件**：
- `src/types/game.ts` — 新增 `MarketEventState` 接口
- `src/stores/game.ts` — 市场事件状态机 + 轮询逻辑
- `src/views/RatRaceView.vue` — 市场面板 UI 改造

**验证**：单人正常 → 多人轮流操作 → 无资产玩家自动跳过 → 全部操作完可结束回合 → 刷新后状态保留

### 需求 6：资产卖出机制优化

**What**：增强卖出体验：数量选择、价格显示、银行弹窗资产 Tab、市场横幅。

**Why**：当前卖出入口隐蔽、操作不直观、无数量控制。

**How**：
1. **卖出数量选择器**（股票类资产）：
   - 复用买入的 +/- 按钮 + 输入框模式
   - 显示"单价 × 数量 = 总价"
2. **银行弹窗新增"资产" Tab**：
   - 分类显示：股票、房产、企业
   - 显示成本、当前市值、月现金流
   - 市场风云时可直接在此处卖出
3. **市场风云横幅**：
   - 棋盘顶部显示持续横幅："市场风云：XX股票涨至$Y"
   - 点击可展开卖出面板
4. **配合需求 2**：多玩家轮询时，每个玩家都有自己的可卖资产列表

**修改文件**：
- `src/stores/game.ts` — `sellAssetToMarket` 支持指定玩家 ID
- `src/views/RatRaceView.vue` — 市场面板数量选择器 + 横幅
- `src/components/BankModal.vue` — 新增资产 Tab

**验证**：可选择卖出数量 → 价格正确 → 银行中可查看资产 → 市场横幅明显 → 多玩家各自操作


## 五、关键技术决策

| 决策点 | 方案选择 | 理由 |
|--------|----------|------|
| 棋盘布局 | absolute 定位 + 百分比计算 | 精确控制、灵活、与现有卡片 UI 风格一致 |
| 市场多玩家 | 轮询式状态机 | 符合桌游实际玩法，状态迁移清晰 |
| 骰子动画 | CSS + JS 组件，先算后播 | 零依赖，性能好，可复用到快车道 |
| 双骰提示 | 三层：徽章 + 按钮 + 消息 | 确保用户不会错过 buff 状态 |
| 卖出数量 | 复用买入 +/- 模式 | 交互一致，降低认知成本 |
| 资产查看入口 | 银行弹窗资产 Tab | 符合"银行管资产"心智模型 |
