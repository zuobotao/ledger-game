## Bug：多 AI 玩家流程终止

### 现状分析

**症状**：多个 AI 玩家时，第一名玩家投一次骰子后流程终止，没有后续动作。

**可能原因（按概率排序）**：

1. **快车道市场事件的 `aiHandleMarketEvent` while 循环阻塞**
   - 新改的 `applyMarketEvent` 会设置 `marketEventState`，进入多玩家轮询模式
   - `aiHandleMarketEvent` 用 while 循环处理所有 AI 玩家，但可能因条件判断错误导致死循环或提前退出后状态不一致
   - 关键：`aiHandlePendingAction` 中 `case 'market'` 直接调用 `aiHandleMarketEvent()`，但这个函数是为老鼠圈设计的，在快车道的上下文（`pendingAction.type === 'market'`）中可能状态不匹配

2. **`moveToNextPlayer` 后 AI 自动触发失效**
   - 市场事件处理完后，`dismissMarketEvent` 的最后是否正确推进到下一个玩家？
   - `moveToNextPlayer` 中的 `setTimeout(runAITurn, 100)` 是否在所有路径下都能触发？

3. **快车道新增的 market pending action 没有正确收尾**
   - 市场事件处理完后，`pendingAction.type` 是否被正确清除？
   - `turnStatus` 是否回到 `idle`？

### 排查与修复方案

#### 第一步：定位 Bug

在关键节点增加日志，复现 bug 后查看终止时的状态：
- `pendingAction.type`
- `turnStatus`
- `marketEventState.phase`
- `currentPlayerIndex`
- `isAIThinking`

#### 第二步：修复 `aiHandleMarketEvent` 在快车道的兼容性

`aiHandleMarketEvent` 函数（game.ts 2282 行）当前假设 `marketEventState` 存在且 `pendingAction.type === 'market'`。在快车道中，`applyMarketEvent` 也会设置 `marketEventState`，所以理论上应该可以工作。

但需要检查：
- `dismissMarketEvent` 最后是否调用了 `moveToNextPlayer`？
- 如果是，是否会与 `aiHandlePendingAction` 返回后的 `runAITurn` 流程冲突（双重推进）？

**修复策略**：
- 如果 `dismissMarketEvent` 已经推进了玩家，那么 `aiHandlePendingAction` 返回后，`runAITurn` 中的 `moveToNextPlayer` 会造成双重推进
- 解决方案：在 `aiHandleMarketEvent` 处理完所有 AI 玩家后，不应该再由外层的 `moveToNextPlayer` 推进
- 或者：`aiHandleMarketEvent` 只处理当前 AI 玩家的回应，不推进轮询，由外层统一管理

**更简单的方案**：在 `aiHandlePendingAction` 的 `case 'market'` 处理完后，检查是否已经推进了玩家（`turnStatus === 'idle'` 且当前玩家不是 AI），如果是则 return 而不再调用 `moveToNextPlayer`。

#### 第三步：确保所有 pending action 类型都有 AI 处理

检查 `aiHandlePendingAction` 的 switch 是否覆盖了所有可能的 `pendingAction.type`：
- `opportunity` ✅
- `market` ✅
- `doodad` ✅
- `charity` ✅
- `layoff` ✅
- `fast_track_opportunity` ✅
- `fast_track_dream` ✅
- `bankrupt` ✅
- `need_loan` ❓（在 doodad case 中处理了吗？）

### 修改文件

| 文件 | 改动类型 | 说明 |
|------|----------|------|
| `src/stores/game.ts` | 修改 | 修复 `aiHandleMarketEvent` 与 `runAITurn` 的玩家推进冲突；确保所有 pending action 类型都有 AI 处理路径 |

### 验证步骤

1. 启动 6 个 AI 玩家的游戏，观察是否能持续运行至少 50 回合
2. 检查玩家轮转是否正确（currentPlayerIndex 循环变化）

## 优化 2：弹窗遮挡图标修复

### 现状

`GameSummary.vue` 弹窗使用 `fixed inset-0 z-50` 全屏覆盖，弹窗内部顶部有一个大图标。但用户说"遮挡图标了"——可能是指：
1. 弹窗遮挡了背景棋盘上的某些图标
2. 弹窗内部的图标被弹窗的其他元素遮挡
3. 弹窗的关闭按钮（X）位置不对，被其他元素遮挡

结合用户描述"原始资本积累、资本游戏完后的弹窗遮挡图标了"，最可能是指弹窗顶部的大图标被标题栏或关闭按钮遮挡，或者图标位置不合理。

另一种可能：弹窗的 z-index 或位置导致它遮挡了页面顶部的导航/操作图标。

### 方案

1. 检查 GameSummary 弹窗的布局，确保图标区域有足够的 padding，不被关闭按钮遮挡
2. 调整图标大小或位置，确保在 `rat_race_end` 和 `victory` 场景下图标完整显示
3. 如果是弹窗位置问题，调整弹窗的 top padding 或整体位置

|------|----------|------|
| `src/components/GameSummary.vue` | 修改 | 调整弹窗顶部图标区域的布局，确保图标不被遮挡 |

## 优化 3：阶段结束展示年龄 + 总结评价

### 现状

`GameSummary.vue` 的 `rat_race_end` 场景显示"成功完成原始资本积累"，但没有显示当前年龄，也没有阶段评价。

### 方案

在 `GameSummary` 组件的概览 section 中增加：

1. **当前年龄显示**：从玩家数据计算并显示（如"当前年龄：32 岁 4 月"）
2. **阶段总结评价**：根据玩家的财务表现给出评级和评价文字

**评级维度**：
- 用时（回合数/年龄）：越年轻完成越好
- 资产增长倍数：初始 vs 最终
- 被动收入达成速度
- 投资组合多样性

**评级等级**：S / A / B / C / D 五档

**评价文字示例**：
- S 级："投资天才！年纪轻轻就实现了财务自由，你的资产增长速度令人惊叹。"
- A 级："优秀的投资者！在合理的时间内完成了原始资本积累，财务决策稳健。"
- B 级："不错的表现！通过努力积累了足够的被动收入，继续保持。"
- C 级："勉强达标。虽然实现了目标，但过程中可以更高效地配置资产。"
- D 级："险象环生。花了很长时间才达成目标，需要优化投资策略。"

### 数据来源

GameSummary 组件已经接收 `player` prop，包含：
- `cash`（现金）
- `assets`（资产列表）
- `totalAssets`（总资产）
- `cashFlow`（月现金流）
- `financialSnapshots`（财务快照，可计算回合数）

年龄计算：`START_AGE + Math.floor(turn / 12)` 岁 + `turn % 12` 月

|------|----------|------|

## 优化 4：历史对局功能

### 功能概述

保存每局游戏的完整数据，用户可以在首页查看历史对局列表，点击进入详情页查看：
- 对局基本信息（时间、玩家数、结果、用时）
- 数据明细（财务快照、资产变化、交易记录）
- 数据分析（财富增长曲线、资产配置、收支分析）
- AI 建议（基于对局表现的改进建议）

### 数据设计

#### 历史对局存储结构（localStorage）

```typescript
interface GameHistoryRecord {
  id: string                    // 唯一 ID
  startTime: number             // 开始时间戳
  endTime: number               // 结束时间戳
  playerCount: number           // 玩家数量
  humanPlayerId?: string        // 人类玩家 ID（观战模式没有）
  result: 'victory' | 'game_over' | 'retirement' | 'in_progress'
  winnerId?: string             // 胜利者 ID
  players: {
    id: string
    name: string
    color: string
    isAI: boolean
    profession: string
    result: 'victory' | 'bankrupt' | 'playing'
    finalNetWorth: number
    finalCashFlow: number
    finalAge: { years: number; months: number }
    totalTurns: number
  }[]
  // 详细数据（可选，占用空间大，默认存最近 5 局的详情）
  details?: {
    financialSnapshots: FinancialSnapshot[]  // 人类玩家的财务快照
    transactions: Transaction[]              // 交易记录
    assets: Asset[]                          // 最终资产列表
    liabilities: Liability[]                 // 最终负债列表
  }
}
```

存储 key：`cashflow_history`，最多保存 50 局，details 最多保存最近 5 局。

### 页面设计

#### 1. 首页增加历史对局入口

在 `HomeView.vue` 中增加"历史对局"按钮或卡片区域，显示最近几局的简要信息。

#### 2. 历史对局列表页（`/history`）

- 顶部：标题 + 清空按钮
- 列表：每局一张卡片，显示时间、结果、玩家数、最终净值
- 点击卡片进入详情

#### 3. 历史对局详情页（`/history/:id`）

Tab 结构：
- **概览**：对局基本信息 + 最终结果 + 玩家排名
- **数据明细**：财务快照表格 + 交易记录列表
- **数据分析**：财富增长曲线 + 资产配置饼图 + 收支柱状图（复用 FinancialCharts 组件）
- **智能建议**：基于对局数据的 AI 建议（规则引擎生成，不依赖外部 API）

### 智能建议规则（规则引擎）

根据对局数据生成建议：
1. **用时过长**：如果超过 20 年才进入快车道 → "建议提高投资效率，更早配置生息资产"
2. **过度依赖单一资产**：如果某类资产占比 > 70% → "资产配置较为集中，建议分散投资降低风险"
3. **现金持有过多**：如果现金占总资产 > 30% → "现金占比较高，可以考虑更多投资机会"
4. **负债过高**：如果银行贷款 > 总资产 30% → "杠杆使用较激进，注意控制风险"
5. **收入来源单一**：如果只有 1-2 种被动收入 → "被动收入来源较少，建议拓展多元收入"
6. **慈善捐赠少**：几乎没有慈善 → "慈善可以带来额外骰子次数，善加利用可以加速进度"
7. **保险意识**：没有买保险且发生过意外支出 → "建议购买保险防范意外风险"

## 假设与决策

1. **多 AI 流程终止 Bug 根因**：假设是市场事件处理与玩家推进的冲突，具体需要加日志确认。如果不是，将通过测试脚本定位。
2. **弹窗遮挡图标**：假设是 GameSummary 内部图标布局问题，具体需查看截图后调整。
3. **历史对局存储**：使用 localStorage，最多 50 局摘要 + 5 局详情，平衡数据完整性和存储空间。
4. **智能建议**：使用规则引擎（if-else）生成，不依赖外部 AI API，保证离线可用和响应速度。
5. **自动化测试**：使用 Node.js 直接运行 store 逻辑，比浏览器测试更快更稳定。
6. **财务图表复用**：历史详情页的数据分析 tab 复用 FinancialCharts 组件，需要将其改为支持 props 传入数据。
