## 1. 修改了什么（按 Phase）

### Phase 8 · 完整 Single E2E → `playtest/scenarios/single-finance-flow.spec.ts`（新增）

单人财务闭环 E2E，覆盖「银行」全部 tab 的完整操作链，并做财务不变量断言：

| 操作 | 断言要点 |
|---|---|
| 存款 | 现金减少、存款增加、净资产不变 |
| 取款 | 存款减少、现金增加、净资产不变；不能超过存款 |
| 银行大额贷款 | 现金增加、负债<sup>月供</sup>增加、净资产不变 |
| 还款 | 全额还清负债后月支出下降；部分还款不降低月支出（符合设计） |
| 保险 | 购买失业保险后月支出上升、资产负债联动正确 |
| 财务报表 | tab 内容展示、无 console error |

要点：
- **避免 FastTrack**：不依赖 `fasttrack-seed.json`，而用确定性财务操作驱动，规避已知 seed 不稳定性。
- **不变量优先**：以「净资产守恒」「月支出升降」做硬断言，而非仅停留在按钮可点。
- 录屏 / 失败 trace 落盘 `playtest/runs/`，多个截图（含移动端模式）随报告留存。

### Phase 9 · 完整 Multiplayer E2E → `playtest/scenarios/multiplayer-complete-e2e.spec.ts`（新增）

双浏览器（Host/Guest）完整多人对局 E2E，覆盖：

| 环节 | 校验 |
|---|---|
| 建房 / 加入 / 开局 | 两页进入同一局，`mp-players` 双方一致 |
| 回合交替 | 用 `pickButton` 保证 turn 交替推进，不出现单人连掷 |
| 状态同步 | 每步动作后双方 `stateHash` 收敛一致（权威服务端为唯一真值） |
| 财务操作 | 存款 / 取款 / 贷款 / 还款 / 保险在真实 UI 中多人闭环 |
| 断线重连 | 中途 `page.goto('/#/multiplayer')` 触发 autoReconnect，重连后状态 hash 与权威一致并继续同局 |

要点：
- **确定性 `pickButton`**：把权威 `allowedActions` 映射到按钮 `testid`；待定事件优先，未掷骰先掷、已掷骰结束回合，确保回合推进而非死锁。
- **hash 收敛判定**：每次动作后等 hash 变化再决定后续，避免「点买被拒后抢点放弃」的竞态。
- **SPA 导航代替硬刷新**：重连后用 `window.location.hash` 导航保留已恢复的 store 单例，避免刷新清空状态。

### 真实缺陷修复：reconnect 丢失 `playerMap`（多人断线重连 isMyTurn 恒 false）

- **现象**：多人重连成功后，客户端 `myGamePlayerId` 为空，`isMyTurn` 恒为 `false`，玩家无法操作。
- **根因**：`reconnect_snapshot` 报文只下发 `state / turn / stateHash / sequence`，未下发「座位号 → 局内游戏玩家 id」映射；重连客户端无法据此定位「自己」，回合判断失效。
- **修复**（3 处，最小改动）：
  - `src/network/protocol.ts`：`ReconnectSnapshotMessage` 增加 `playerMap?: Record<string, string>`（座位号 → 局内玩家 id）。
  - `server/RoomServer.ts`：重连下发时按 `room.players[i]` 与 `snapshot.state.players[i]` 生成 `playerMap`。
  - `src/stores/multiplayer.ts`：收到 `reconnect_snapshot` 时写入 `playerMap.value`。

### 测试可观测性 → `src/main.ts`

`import.meta.env.DEV` 下把 `window.multiplayerStore` 暴露给 E2E，用于校验多人状态 / hash / 回合上下文（与既有 `window.gameStore` 一致）。

### 其它

- `docs/gameplay/BALANCE.md`：同步更新策略模拟对比表（本版本经济曲线微调后的最新数据，非本轮引入，属提交内既有变更）。

## 2. 为什么这么修改

- **单人**：此前 `basic-game` 是 Bot 跑整局（长、慢、结果依赖随机），难以稳定断言具体财务行为。`single-finance-flow` 用确定性操作把「银行闭环 + 财务不变量」固化成可复现用例。
- **多人**：`multiplayer-room` 只覆盖「建/加/开/掷骰」一步，未触及核心财务与重连。Phase 9 把它补全到完整闭环，并把状态同步（hash 一致）作为核心断言。
- **playerMap 修复**：多人最核心的可玩性之一是断线重连继续同局；身份（座位 → 局内玩家）一旦丢失，重连即失去操作权。此修复属于 multiplayer authority 真实缺陷，必须由服务端权威补发。

## 3. 复用的已有能力 / 未动的部分

1. 加固 FastTrack E2E seed：换「进入后半程但未结束」的稳定 seed，或对 `driveFastTrack` 加入结束即停的守卫，消除 `finished` 竞态。
