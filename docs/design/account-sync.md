# 邀请制账户与云同步设计

**状态：** 设计完成，尚未实现登录、服务端存储或跨设备同步  
**日期：** 2026-09-08  
**范围：** 历史复盘、中途存档、邀请制账户和跨设备云同步

## 1. 目标与边界

Ledger 继续以本地匿名存档为默认路径。邀请制账户只用于把同一位用户在受信设备上的游戏存档同步到云端，不建立公开社交身份，也不接收真实金融账户、支付信息或投资组合数据。同步的数据仍是虚构的游戏状态、历史对局摘要和必要的同步元数据。

本设计不实现登录，也不决定具体云厂商、邮件服务或商业化方案。实现前必须补充隐私政策、服务条款、数据删除/导出流程和服务端运维方案，并完成安全评审。

## 2. 现有文档约束

- `docs/legal/AI_DATA_POLICY.md` 的数据最小化原则继续适用：不得上传真实姓名、邮箱、电话、银行、券商、支付或其他现实财务信息；若未来接入外部 AI，云同步数据也不得绕过该边界进入 AI 请求。
- `docs/legal/FINANCIAL_DISCLAIMER.md` 的教育模拟声明继续显示在产品内。云端保存的是虚构游戏数据，不代表现实投资表现，也不提供投资建议。
- 本地匿名存档不要求账户；用户可以在不联网、不注册的情况下开始、暂停、恢复和删除游戏。
- 账户同步不改变游戏规则、历史记录的展示含义或本地存档的 schema 兼容策略。

## 3. 邀请制流程

### 3.1 创建与绑定

1. 用户在“同步存档”中选择“创建邀请制账户”，本机生成设备密钥和安装标识。
2. 服务端创建不可猜测的账户 ID，并返回一次性邀请代码或短时邀请链接。邀请代码只用于首个设备绑定或新设备加入，不作为长期登录凭据。
3. 用户在第二台设备输入邀请代码；两台设备通过短时授权流程确认绑定。代码过期、已使用或尝试次数超限时必须明确失败，不泄露账户是否存在。
4. 绑定完成后，设备取得独立设备会话和同步权限。用户可在任一已绑定设备查看设备列表并撤销设备。

### 3.2 恢复与退出

- 已绑定设备使用本地设备密钥恢复会话；会话过期或被撤销时回退到本地匿名模式，不能阻断继续玩单机游戏。
- 用户可“暂停同步”而保留本地存档，也可“退出此设备”并删除本机的同步会话材料。退出不删除云端账户或其他设备。
- “删除账户及云端存档”必须是单独的高风险操作，要求再次确认并提供宽限期；删除期间允许用户导出本地副本。
- 丢失全部已绑定设备且没有可用邀请代码时，不承诺通过邮箱、手机号或人工身份核验恢复账户。这样避免引入未设计的身份系统。

## 4. 密钥与会话

- 每台设备生成非对称设备密钥对；私钥只保存在系统安全存储（浏览器优先使用 Web Crypto/可导出的受保护密钥容器），不上传明文私钥。
- 服务端保存设备公钥、设备状态、创建时间、最后使用时间和撤销时间。设备密钥用于证明设备身份，不能直接读取存档。
- 会话使用短时访问令牌和可轮换刷新令牌。访问令牌仅放在内存；刷新令牌放在受保护存储中，轮换失败或重用时立即撤销该设备会话。
- 密码不落盘：首期流程不设置可恢复密码，也不把邀请码、令牌、密钥或其明文派生物写入游戏存档、日志、分析事件或 URL 查询参数。
- 所有同步请求使用 TLS，并绑定设备会话、请求时间窗和单调递增客户端序号。服务端拒绝过期令牌、已撤销设备和不匹配的账户/设备组合。

## 5. 数据模型

服务端只保存同步所需的最小字段；示意模型如下：

```text
Account {
  accountId, createdAt, status, schemaVersion,
  createdByDeviceId, deletedAt?
}

Device {
  deviceId, accountId, publicKey, label?, createdAt,
  lastSeenAt, revokedAt?, keyVersion
}

SaveSnapshot {
  saveId, accountId, sourceDeviceId, gameId?,
  schemaVersion, revision, clientSequence,
  statePayload, stateHash, updatedAt, deletedAt?
}

ReplaySummary {
  replayId, accountId, saveId?, schemaVersion,
  summaryPayload, eventLog?, createdAt, updatedAt, deletedAt?
}

SyncTombstone {
  objectType, objectId, revision, deletedAt, expiresAt
}
```

`statePayload` 只包含游戏所需的虚构状态和历史摘要；不得出现姓名、邮箱、电话、地址、支付信息、真实银行/券商字段或自由文本个人资料。服务端应按字段白名单序列化，而不是把整个浏览器存储目录上传。`eventLog` 如用于确定性复盘，必须限制大小、版本和保留期，并与当前存档分开。

## 6. 离线优先与同步语义

- 本地 IndexedDB 是读写主路径；开始游戏、回合操作、历史查看和中途保存不依赖网络。
- 网络可用时，客户端在后台上传经过 schema 校验的快照和删除标记；同步失败进入重试队列并使用指数退避，不阻塞游戏 UI。
- 首次绑定采用“本地优先”：用户明确选择要上传的本地存档。云端已有存档时先展示摘要、时间和设备来源，要求选择合并或保留副本，禁止静默覆盖。
- 下载快照先写入临时记录、校验完整性和 schema，再原子替换本地版本；校验失败保留原存档并显示可理解的恢复提示。
- 每个存档带 `schemaVersion` 和 `revision`。客户端只接受已知版本；未知版本保留为不可编辑的云端副本，等待迁移，不直接丢弃。

## 7. 冲突合并与删除

- 同一 `saveId` 的普通状态采用版本号和客户端单调序列检测冲突。若两个设备都从同一 revision 修改，视为真正冲突。
- 游戏状态不做字段级盲目合并：展示两份摘要（回合、现金流、净资产、更新时间和设备），由用户选择一份作为当前存档，另一份保留为历史副本。
- 历史复盘事件若事件 ID、来源设备和顺序连续，可按事件 ID 去重后追加；发现缺口、重复或 schema 不一致时转为只读副本，交给用户选择。
- 删除采用带 revision 的 tombstone，避免离线设备重新上传已删除数据。tombstone 在所有活跃设备确认或超过保留期后才可清理。
- 服务端绝不以“最后写入”静默覆盖较新的用户进度；冲突和自动合并结果都要记录可审计的原因。

## 8. 防重放、限流与滥用控制

- 每次写入携带设备会话、请求 ID、时间戳、签名/认证证明和严格递增的 `clientSequence`；服务端对已处理请求做幂等去重。
- 令牌刷新只允许一次成功轮换；旧刷新令牌重用即撤销该设备会话并要求重新邀请绑定。
- 邀请代码使用高熵随机值，短时有效、单次消费、错误次数有限，并按账户、设备、IP/网络边界分层限流。错误响应保持模糊，避免枚举账户或有效代码。
- 上传大小、对象数量、事件长度、设备数量和重试频率均有上限；超限时返回可恢复错误，不循环重试。
- 服务端记录最少的安全审计字段（时间、设备 ID、结果、错误类别）；禁止记录令牌、邀请码、私钥和完整游戏 payload。

## 9. 迁移路径

1. **当前阶段：** 仅本地匿名存档和本地历史；继续使用现有 `schemaVersion`，不引入账户字段。
2. **设计验证：** 增加客户端序列化白名单、快照 hash、导入/导出测试和离线冲突模拟；先用本地 mock 服务验证协议。
3. **灰度同步：** 小范围邀请绑定，默认关闭自动上传，提供明确的本地/云端摘要和删除入口；观测失败率、冲突率和撤销行为，不收集现实身份信息。
4. **正式启用：** 完成隐私政策、服务条款、数据保留/删除、事故响应和安全评审后，逐步开放跨设备同步。
5. **版本迁移：** 迁移器必须是显式、可测试、幂等的 `schemaVersion` 转换；迁移失败保留原始快照和可读错误，禁止破坏性覆盖。旧本地存档仍可离线读取。

## 10. 风险边界与验收门槛

主要风险包括设备丢失、邀请代码转发、恶意重放、云端误覆盖、schema 漂移、同步元数据泄露和用户误把模拟数据当作现实财务记录。首期方案通过短时一次性邀请、设备撤销、最小字段、离线优先、显式冲突选择和不保存密码降低风险，但不能替代端到端安全评审或服务端运营控制。

实现前必须满足：

- 隐私政策明确云端字段、保留期、删除和导出；财务免责声明仍在账户/同步入口可见。
- 单元与集成测试覆盖邀请过期/重用、设备撤销、刷新令牌重用、重复请求、离线队列、冲突、删除 tombstone 和未知 schema。
- 安全测试确认日志、URL、分析和错误响应不泄露密码、令牌、邀请码、私钥或真实个人/金融数据。
- QA 在 PC、手机、断网恢复和双设备场景记录证据；在完成这些门槛前，云同步不得标记为已实现。
