# Ledger v2.3.0 实现报告

> **版本定位：让玩家真正看懂自己的财务状态，并让每一次机会都变成一个可理解、可操作的决策。**
> 范围收敛：本轮只打磨单机核心玩法，不做登录 / 联网 / 多人房间 / AI 大改造 / 新增资产类别 / 重写 Engine。

---

## 1. 修改了什么（按 Phase）

### Phase 1 · 现状审计 → `docs/V2.3_AUDIT.md`
扫描确认：数据模型（`Asset` 的 `cost/marketPrice/loanAmount/monthlyLoanPayment/cashFlow/quantity`、`savings`、`childrenCount`、`saveState/loadState`）与相关引擎（`assetEngine`、`transactionEngine`、`financialEngine`、`simulation`、`randomSource`、`eventLog`）均已存在，**缺口主要在于 UI 未暴露，以及缺经济曲线数据支撑**。据此确定后续各 Phase 以「复用 + 暴露」为主，不推倒重写。

### Phase 2 · 玩家状态（长期信息层）→ `CoreMetricsBar.vue`
玩家财务核心指标成为**常驻信息条**，始终可见：现金、Cash Flow、资产、负债、净资产、**存款**、**孩子数量**。孩子数量与存款加入 `CoreMetricsBar`（带图标配色），满足 P0「玩家随时知道我现在是什么状态」。

### Phase 3 · 资产信息统一 → `RatRaceView.vue` / `FastTrackView.vue`
- 股票卖出面板补齐**买入均价 / 卖出价 / 本次收益 / 剩余成本**（基于 `getStockHolding` 的加权平均成本）。
- 房地产 / 企业资产显示**贷款金额 + 月供**，与现有 成本/市价/现金流 并列。
- Fast Track 资产面板已含 成本/市价/总成本/总市值/浮动盈亏/收益率/月现金流，本轮衔接确认。

### Phase 4 · 现金 / 存款 → `BankModal.vue` + `test/unit/savings.spec.ts`
- 存款 UI 增加「取出」，含 `$100/$500/$1,000/全部`快捷金额与边界禁用。
- 新增单测覆盖：**不能取出超过存款、不能存入超过现金、存取不改变净资产、金额一致、交易记录落账**。

### Phase 5 · 孩子机制 → `game.ts`
- 孩子事件从「一声恭喜」改为结构化反馈：`孩子数量 old → new` + `每月支出 +X` + `新的月现金流`，并写入交易记录。
- 孩子数量已常驻 `CoreMetricsBar`。
- **频率 Simulation 验证（见 §5）**：40 回合平均 1.59 个、前 10 回合 0.39、首个孩子约第 13 回合、最大连续生育 0.86 —— 现有的冷却（`MIN_TURNS_BETWEEN_CHILD_EVENTS=3`）+ 上限（`MAX_CHILDREN`）机制本身已把密度控制在合理区间，**无需再调整**。

### Phase 6 · 经济平衡（本轮核心玩法改动）→ `game.ts` + `scripts/sim-batch.ts`
新增批量确定性对局模拟器 `scripts/sim-batch.ts`（1040 局 / 40 回合，覆盖 10 个职业），先分析后修改。
修改点：**渐进式机会梯度** —— 当玩家现金不足以覆盖最便宜大机会的首付时，把大机会格替换为可行的小/中机会；随财富跨越阶梯解锁真实大机会。数据前后对比见 §4。

### Phase 7 · 移动端
Rat Race / Fast Track 采用同一套响应式纵向结构：**棋盘(order-1，等比缩放) → 财务面板(order-2，可折叠)**，全程无 `overflow-x:hidden` 假修（校验源码确认）。播放器通过 `⌘/ctrl` 下 `min-h-[38vh]` + 居中缩放避免裁剪。390×844 无溢出布局用例通过，移动端完整对局跑通（见 §6）。

### Phase 8 · 保存 / 继续 → `HomeView.vue` + `game.ts`
- 存档增加 **`schemaVersion: 1`**（`SAVE_SCHEMA_VERSION`），loadState 遇到更高版本安全丢弃，为未来迁移铺路。
- 首页识别未完成对局并展示「继续游戏」卡片：玩家 / 阶段 / 回合数 / 人数 / 现金 / Cash Flow。
- 存在存档时「开始新游戏」弹**覆盖确认**；无存档则保持「开始游戏」。
- 新增单测：`schemaVersion` 写入、`resumableGame` 摘要、未来版本存档安全丢弃。

### Phase 9 · 自动 Playtest（验证）
Desktop + Mobile 各完整跑通 Random Bot 一局（51 回合），无 `pendingAction` 死锁、无 NaN / 负数异常 / 横向溢出。见 §6。

## 2. 为什么这么修改

| 决策 | 动机 |
|------|------|
| 渐进式机会梯度（而非调概率） | Simulation 证明大机会占 33.6% 且**前 5 回合 100% 买不起**，直接调概率会同时削弱后期大机会的存在感；渐进解锁能保留「大机会 = 进阶奖励」的同时消除「只能看着它离开」。 |
| 存取不产生利息 | 第一版不引入新经济系统，避免 Net Worth 语义漂移，只改变资金位置。 |
| 存款/孩子 常驻信息条 | 让「状态」成为长期 UI 层而非一次性弹窗，对应反馈「忘了存了多少钱 / 有几个孩子」。 |
| 复用现有字段 | `cost/marketPrice/loanAmount/monthlyLoanPayment/cashFlow/quantity` 已完整覆盖，不为展示信息增加重复字段。 |
| 保存只做产品化 | 现有 `saveState/loadState/localStorage` 已可用，只加 `schemaVersion` 与首页入口，禁止重写。 |
| 先修既存失效单测 | `state-hash.spec.ts` 语法错误、`game-engine` net worth 断言用旧 `game_over` 枚举 → 更新为当前模型，保证「原有测试通过」。 |

---

## 3. 复用的已有能力

- 数据模型字段（`savings`、`childrenCount`、`Asset.*`）— 全部复用，零新增存储字段。
- `financialEngine.recalcPlayerFinancials / calcPlayerNetWorth`、`assetEngine.calcTotalAssetValue`。
- `transactionEngine` 交易记录（含 `savings_deposit/savings_withdraw`、`child`）。
- 保存系统 `saveState/loadState` + `localStorage`。
- 确定性 `randomSource`、`simulation` 引擎，供 `sim-batch.ts` 复用同样的随机模型。
- 孩子事件的冷却+上限常量（`MIN_TURNS_BETWEEN_CHILD_EVENTS`、`MAX_CHILDREN`）。

## 4. Simulation：经济曲线 修改前 vs 修改后（1040 局 / 40 回合）

| 指标 | 修改前 | 修改后 | 解读 |
|------|-------:|-------:|------|
| 机会可负担率（现金≥首付） | 48.9% | **62.6%** ↑ | 更少「只能放弃」 |
| 全程可负担率（含贷款评估 `canPlayerAfford`） | 84.8% | **95.5%** ↑ | 贷款通道利用提升 |
| 前 5 回合可负担率 | 41.7% | **63.2%** ↑ | 前期不再长期买不起 |
| 前 5 回合大机会占比 | 33.2% | **0.17%** ↓ | 大机会不再过早砸脸 |
| 全程大机会占比 | 33.6% | 12.9% ↓ | 回归「大机会 = 进阶奖励」 |
| 大机会买得起率 | 11.1% | **23.0%** ↑ | 遇到大机会时更有能力抓住 |
| 首次买到资产（回合） | 6.6 | **4.9** ↓ | 更快获得第一笔资产 |
| 首次买到会（回合） | 13.5 | 14.1 | 大机会作为中后期里程碑 |
| 最长连续买不起 | 3.8 | **2.7** ↓ | 减少长期无力感 |
| 买不起占比（修正统计后） | ~51% | **37.4%** ↓ | 「需要选择但不会被长期劝退」 |

> 目标达成：玩家现在经常要**做选择**，但不再长期只能放弃 —— 理想体验曲线 `小 → 中 → 大` 成立。

## 5. Simulation：生育频率验证（1040 局 / 40 回合）

| 指标 | 值 | 结论 |
|------|---:|------|
| 每局平均孩子数 | 1.59 | 适中 |
| 前 10 回合平均新增 | 0.39 | 前期低频 |
| 首个孩子平均回合 | ≈13 | 非前期随机连发 |
| 最大连续生育 | 0.86 | 少见连发 |
| 分职业差异 | 1.4~1.8 个/局 | 各职业接近 |

**结论：现有冷却+上限已足够，不调整。孩子是长期管理变量而非前期随机惩罚的目标已满足。**

## 7. 已知问题

1. **Fast Track 移动端未经完整对局验证**：25 回合内 Random Bot 未晋升快车道，FastTrackView 移动端仅通过布局一致性确认（与 Rat Race 同一响应式结构）。建议在后续用一个「预设晋升到快车道」的 seed / 场景专项验证。
2. **经济曲线仍偏向随机 bot**：`buyOpportunity(1)` 的「温和买入」策略使部分大机会卡在买得起时仍未触发完整衡量；更细的 AI 决策留给 v2.5。
3. `docs/gameplay/BALANCE.md` 有一份工作区既存更新（AI 平衡表数据），与本迭代无直接关联，保留未动。
4. Fast Track 资产面板成本/现价基于 `cost*quantity` 估算，未对多笔不同成本合并做加权平均（股票已按加权平均成本处理）。
