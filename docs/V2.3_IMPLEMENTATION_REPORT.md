# Ledger v2.3.0 实现报告

> **版本定位：让玩家真正看懂自己的财务状态，并让每一次机会都变成一个可理解、可操作的决策。**
> 范围收敛：本轮只打磨单机核心玩法，不做登录 / 联网 / 多人房间 / AI 大改造 / 新增资产类别 / 重写 Engine。

## 2. 为什么这么修改

| 决策 | 动机 |
|------|------|
| 渐进式机会梯度（而非调概率） | Simulation 证明大机会占 33.6% 且**前 5 回合 100% 买不起**，直接调概率会同时削弱后期大机会的存在感；渐进解锁能保留「大机会 = 进阶奖励」的同时消除「只能看着它离开」。 |
| 存取不产生利息 | 第一版不引入新经济系统，避免 Net Worth 语义漂移，只改变资金位置。 |
| 存款/孩子 常驻信息条 | 让「状态」成为长期 UI 层而非一次性弹窗，对应反馈「忘了存了多少钱 / 有几个孩子」。 |
| 复用现有字段 | `cost/marketPrice/loanAmount/monthlyLoanPayment/cashFlow/quantity` 已完整覆盖，不为展示信息增加重复字段。 |
| 保存只做产品化 | 现有 `saveState/loadState/localStorage` 已可用，只加 `schemaVersion` 与首页入口，禁止重写。 |
| 先修既存失效单测 | `state-hash.spec.ts` 语法错误、`game-engine` net worth 断言用旧 `game_over` 枚举 → 更新为当前模型，保证「原有测试通过」。 |

# 增补 · 机会系统机制升级（P0-2）与 Rat Race → Fast Track 打通（P0-3）

> 反馈触发：内测玩家反映「完成了初始资本积累、还清欠款后，进不去资本游戏」，以及「大机会过度依赖随机骰子、连续大机会产生挫败」。本增补把 v2.3 从「核心体验打磨」推进到「核心循环机制打通」。范围仍收敛在单机玩法，不引入登录 / 联网 / 多人房间 / 重写 Engine。

## 10. P0-3 审计结论：玩家为什么「进不去资本游戏」

### 10.1 规则核对
按 PRD / `turnEngine` 现有定义，Rat Race → Fast Track 的脱离规则是：
```
canEnterFastTrack(player) = player.phase === 'rat_race' && player.passiveIncome >= player.totalExpenses
```
即「被动收入覆盖总支出」——不是「还清所有贷款」。这也是内测玩家心理预期（《Rich Dad》式「被动收入 > 支出 =财务自由」）的一致表达。

### 10.2 真实根因：不是规则错，而是「无反馈 + 状态陈旧」
审计确认三处导致玩家「卡住」的实际问题，全部修复：

1. **无资格反馈**：玩家只能「看到还完最后一笔贷款、什么都没发生」，无法得知自己还差多少被动收入才能进入资本游戏。
2. **移动端无入口**：`RatRaceView.vue` 的「进入资本游戏」按钮用了 `hidden sm:inline-flex`，手机端根本不可见。
3. **状态派生陈旧风险**：还清贷款后虽有 `payoffLiability` 触发 `recalcPlayerFinancials`，但此前缺少「取得资格后立即、主动、可见地」告知玩家的机制。

**修复**：新增 `FastTrackEligibility.vue` 常驻资格面板（满足/不满足项 + 缺口 + 进入按钮）、`getFastTrackEligibility(player)` 纯函数（Engine 层唯一资格来源）、以及 `enterFastTrack()` / `fastTrackEligibility` 状态。资格是**派生状态**，永不自持，刷新页面自动由 `passiveIncome` / `totalExpenses` 重算（Scenario D/E 验证）。

## 12. P0-2 Opportunity System 交付

遵循设计约定：「机会存在，能力逐渐获得」，而非「玩家变强系统才给大机会」；且禁止「直接把大机会概率调低」。

### 12.1 新增独立层
- **`opportunityEvaluator.ts`**（纯粹合层）：根据玩家 `cash/savings/cashFlow/netWorth` 与卡面成本，判定参与方式 `full / finance / partial / none` + 所需资金 / 缺口 / 现金回报 / headroom / FastTrack 资格，产出 `hintKey`（affordable / need_finance / need_save / eligible_fast_track）。
- **`opportunitySelector.ts`**（机会生成层）：`rarity`（COMMON/UNCOMMON/RARE/LEGENDARY）+ 权重 + `bigCooldownRecovery` 冷却恢复 + `resolveOpportunityTier` 席位判定。
- **`OpportunityCard.rarity`**：类型层新增稀缺度字段。

### 12.2 接入大机会冷却（保留随机性）
`game.ts` 中：当落在大机会格时，先按「资金是否跨过最便宜大机会首付台阶」决定是否保留 Big；再按 `bigCooldownRecovery`（最近一次 Big 距今回合数的线性恢复，`0.15→1.0`）与一次随机 `roll` 决定本次是否仍兑现为 Big。**不机械禁止**，只是压低刚出现 Big 后的再现概率。

### 12.3 参与方式接入 UI（部分参与机制按 v2.5 延后）
UI 复用 `evaluateOpportunity` 的 `hintKey` 给出「全额可买 / 需要贷款 / 需攒资 / 资格已够」等可读反馈；「联合投资 / 融资形态」的完整多方案参与按路线图延后到 v2.5（`Opportunity Evolution`），不阻塞本轮。

### 12.4 防止「为了测试改生产逻辑」
Selector 增加 `legacyOpportunityMode` 开关，**仅供 `sim-batch.ts --legacy` 做前后对比**；默认关闭，不参与玩法，不持久化。

## 15. 新增已知问题

1. `sim-batch` bot 策略偏保守（温和买入、未充分使用贷款），40 回合内 Fast Track 可达率低（0.5%→1.1%）。真实玩家更长对局 + 更主动配置会显著更高。已用**资格面板 + 单测 A~E** 保证「机制可进、刷新保持」；更真实 AI 决策留给 v2.5。
2. 「部分参与（联合投资 / 融资形态）」仅提供 `hintKey` 文案反馈，完整多方案参与入口按路线图延后到 v2.5 `Opportunity Evolution`。
3. `legacyOpportunityMode` / `setLegacyOpportunityMode` 仅用于仿真对比，属非玩法 API；若后续需要避免暴露，可收敛为模块级开关。
